## General Information

- **Key Name** (required) — a short, identifying name, e.g. `Production
Service Key`. This is how the key appears in the API keys list, so make it
  specific to the service or integration that will use it.
- **Description** — what the key is for and who owns the integration. Useful
  when several keys exist side by side.

### Metadata Tags

Add free-form key/value pairs under **Metadata Tags** for any extra context
you want attached to the key — an environment name, a ticket reference, an
owning team, and so on. Tags are optional and purely informational; they have
no effect on what the key can do.

<Callout type="tip" title="Name keys by service, not by person">
  A key tied to a specific integration (e.g. "Billing Sync") is easier to rotate
  or revoke later than one named after whoever created it.
</Callout>
